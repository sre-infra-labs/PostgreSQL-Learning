# Performance Impact of Your Synchronous Configuration\n\n## The Core Question: Why is `ANY 2 (pg2, pg4)` Slow?\n\nBecause **every single write waits for the slowest replica**.\n\n---\n\n## Timing Breakdown\n\n### Local Write (pg1 → pg2 only, async setup)\n\n```\nClient sends INSERT\n    ↓\n    [0ms]   pg1 receives WAL\n    [1ms]   pg1 writes WAL to disk\n    [2ms]   pg2 receives WAL (same datacenter)\n    [3ms]   pg2 writes WAL to disk\n    [5ms]   pg1 gets ACK from pg2\n    [5ms]   ✅ INSERT committed — return to client\n    ─────────────────────────────\n    [5ms]   TOTAL LATENCY\n```\n\n### Cross-Region Write (pg1 → pg2 + pg4, your sync setup)\n\n```\nClient sends INSERT\n    ↓\n    [0ms]   pg1 receives WAL\n    [1ms]   pg1 writes WAL to disk\n    [2ms]   pg2 receives WAL (Region A, same datacenter)\n    [5ms]   pg2 writes WAL to disk\n    [5ms]   pg1 gets ACK from pg2 ✓\n    ├→ [50ms]  pg4 receives WAL over WAN (Region B, 50-150ms RTT)\n    ├→ [100ms] pg4 writes WAL to disk\n    └→ [150ms] pg1 gets ACK from pg4 ✓  ← SLOWEST\n    [150ms] ✅ INSERT committed — return to client\n    ─────────────────────────────\n    [150ms] TOTAL LATENCY (30x slower!)\n```\n\n---\n\n## Why This is the Actual Latency You Experience\n\n### The Blocking Mechanism\n\n```\nClient Write Time = MAX(latency to pg2, latency to pg4)\n\nNot: pg2_latency + pg4_latency (sequential)\nBut: MAX(5ms, 150ms) = 150ms (parallel, but client waits for all)\n```\n\n### Real Numbers from AWS/Azure Multi-Region\n\n| Scenario | Region A ↔ B Latency | pg1→pg2 | pg1→pg4 | Client Sees |\n|----------|--------|-------|---------|--------|\n| Same AZ | 1ms | 5ms | 6ms | **6ms** |\n| Same Region | 5ms | 5ms | 10ms | **10ms** |\n| Different Region (US-East→US-West) | 50ms | 5ms | 55ms | **55ms** |\n| Different Continent (US→EU) | 150ms | 5ms | 155ms | **155ms** |\n| Poor WAN | 200ms | 5ms | 205ms | **205ms** |\n\n---\n\n## Throughput Impact\n\n### TPS (Transactions Per Second) Comparison\n\n**Async Setup (pg2 only):**\n```\nIf each transaction takes 5ms:\n  TPS = 1000ms / 5ms = 200 TPS\n```\n\n**Your Sync Setup (ANY 2):**\n```\nIf each transaction takes 150ms:\n  TPS = 1000ms / 150ms = 6.7 TPS\n  \n  Lost throughput: 200 - 6.7 = 193.3 TPS (96.6% REDUCTION!)\n```\n\n---\n\n## Real-World Workload Examples\n\n### Workload 1: High-Frequency Trading\n\n```\nNeed: 10,000 TPS with synchronous replication\nYour latency: 150ms for cross-region sync\nYour TPS: 1000/150 = 6.7 TPS ❌\n\nConclusion: NOT SUITABLE\nSolution: Use async replication or keep regional\n```\n\n###
