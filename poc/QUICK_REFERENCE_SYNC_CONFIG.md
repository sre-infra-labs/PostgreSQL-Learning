# Quick Reference: Your Synchronous Configuration\n\n## The Five Settings You Asked About\n\n### 1️⃣ `synchronous_standby_names: ANY 2 (pg2, pg4)`\n\n**In Plain English:**\nWhen you write to pg1, it waits for **ANY 2 of these replicas to say \"I got it\":**\n- pg2 (local, fast: ~5-10ms)\n- pg4 (cross-region, slow: ~50-200ms)\n\n**What this costs:**\n- 🐢 Write latency: +50-200ms (waiting for Region B)\n- 🔒 If pg4 is dead → primary goes read-only\n\n**What you gain:**\n- ✅ RPO = 0 (zero data loss, both pg2 and pg4 have it)\n- ✅ Multi-region protection\n\n**Real-World Example:**\n```\nYou: INSERT INTO users VALUES (1, 'Alice');\n\npg1: Sending to pg2... ✓ Got ACK in 5ms\npg1: Sending to pg4... ✓ Got ACK in 150ms\npg1: \"Both confirmed! INSERT is safe.\" → You: ✅ Command OK\nTotal time: 150ms (limited by slowest = pg4)\n```\n\n---\n\n### 2️⃣ `synchronous_mode: true`\n\n**In Plain English:**\n\"I will NEVER promote a standby unless it has ALL the data that was committed.\"\n\n**What it does:**\n- On failover, Patroni checks: \"Does the new leader have everything?\"\n- Only promotes if answer is YES\n- If NO: keeps primary down until standby catches up\n\n**Prevents:**\n- ✅ Unexpected data loss from promoting an out-of-date standby\n\n**Risk:**\n- ⚠️ Cluster may be read-only temporarily\n\n---\n\n### 3️⃣ `synchronous_mode_strict: false`\n\n**In Plain English:**\n\"If a synchronous standby becomes unreachable, keep serving writes anyway.\"\n\n**What it does:**\n- If pg4 fails: Patroni demotes it from sync status\n- pg1 continues writing with just pg2 as sync\n- Patroni picks another replica to replace pg4\n\n**With `true` (strict):**\n- pg1 would STOP accepting writes\n- Cluster goes read-only\n\n**Your choice:** `false` is better for availability\n\n---\n\n### 4️⃣ `synchronous_node_count: 1`\n\n**In Plain English:**\n\"At least 1 replica must always be in sync mode.\"\n\n**What it does:**\nPatroni continuously monitors and ensures:\n```\nAlways have:  sync_state = 'sync' for at least 1 replica\n\nExample:\npg2: sync_state = 'sync'   ← This one is mandatory sync\npg3: sync_state = 'async'  ← This one is optional\npg4: sync_state = 'async'  ← This one is optional (might be slow)\n\nIf pg2 dies:\n  Patroni picks pg3 or pg4 → Makes it 'sync'\n  Maintains: exactly 1 sync standby\n```\n\n**Note:** This is DIFFERENT from `synchronous_standby_names`\n- `synchronous_node_count = 1`: At least 1 must exist\n- `ANY 2 (pg2, pg4)`: Primary waits for 2 specific ones\n\n---\n\n### 5️⃣ `maximum_lag_on_failover: 1048576` (1 MB)\n\n**In Plain English:**\n\"On failover, I'll promote a standby even if it's up to 1 MB behind.\"\n\n**What it means:**\n```\nIf primary crashes:\n  Check: Is there a standby within 1 MB of the latest WAL?\n  YES → Promote it (may lose up to 1 MB of data)\n  NO  → Keep cluster down, wait for closer standby\n```\n\n**Why 1 MB?**\n- ~5000-10000 transactions in a typical workload\n- ~5-10 seconds of write traffic\n\n**Trade-off:**\n- ✅ Failover is FASTER (doesn't wait for perfect sync)\n- ❌ RPO = 1 MB (may lose some data)\n\n**⚠️ Conflict:**\nYour `synchronous_mode: true` says \"RPO = 0\" but this says \"RPO = 1 MB\"\n\n**Recommendation:**\nSet to 0 for strict RPO = 0:\n```bash\ndocker exec pg1 patronictl -c /etc/patroni/patroni.yml edit-config pg-docker-cls1 \\\n  --force --set maximum_lag_on_failover=0\n```\n\n---\n\n## Your Configuration at a Glance\n\n```\n┌─────────────────────────────────────────────────────────┐\n│ Write Latency:        +50-200ms  (waiting for pg4)      │\n│ RPO (Data Loss):      0-1 MB     (conflict⚠️)          │\n│ Failover Type:        Synchronous (strict checking)     │\n│ Standby Demotion:     Automatic (if fails)              │\n│ Multi-Region:         YES (pg4 in Region B protected)   │\n│ Primary Availability: High (doesn't stop if standby OK)  │\n└─────────────────────────────────────────────────────────┘\n```\n\n---\n\n## What Each Setting Protects Against\n\n| Problem | Protected By |\n|---------|---|\n| Primary crashes, standby is promoted with missing data | `synchronous_mode: true` |\n| Standby dies, primary becomes read-only | `synchronous_mode_strict: false` |\n| Sync standby is too slow | `synchronous_mode_strict: false` (demotes it) |\n| Data is lost in cross-region failover | `synchronous_standby_names: ANY 2 (pg2, pg4)` |\n| Standby elected is too far behind | `maximum_lag_on_failover: 1MB` (allow some loss) |\n\n---\n\n## The Visual Story\n\n```\nNormal Operation:\n  Client → pg1 (write) → waits for pg2 ✓ + pg4 ✓ → SUCCESS\n              ↓\n           (50-200ms latency)\n\npg4 fails:\n  Client → pg1 (write) → waits for pg2 ✓ → SUCCESS\n              ↓\n           (back to fast: ~5-10ms)\n\npg2 fails:\n  Client → pg1 (write) → Patroni demotes pg2 → promotes pg3 or pg4\n              ↓\n           (automatic, ~10 second interruption)\n\nAll Region A fails:\n  Client → pg4 (now leader) → SUCCESS\n              ↓\n           (pg4 has all data due to sync mode)\n```\n"
